## 🎨 Архітектура

### До покращень:
```
User Command
    ↓
NLU Engine (rule-based + LLM)
    ↓
Intent + Entities
    ↓
Execute
```

### Після покращень:
```
User Command + user_id
    ↓
Context Manager (get/create session)
    ↓
NLU Engine (rule + LLM + context)
    ├─ Rule-based (швидкі)
    ├─ LLM-based (складні)
    └─ Context-based (продовження) ← NEW
    ↓
Intent + Entities (з контексту) ← NEW
    ↓
Save to Context ← NEW
    ↓
Execute
    ↓
Save Response to Context ← NEW
```

### ⚠️ Що потребує Ollama LLM (опціонально):

   - Складні продовження діалогу

   - Дуже складні команди
   - Нестандартні формулювання

## 💡 Приклади використання

### Приклад 1: Контекстний діалог
```python
# Користувач A
handle_intent("запусти chrome", user_id="user_A")
handle_intent("і firefox теж", user_id="user_A")  # Розуміє з контексту

# Користувач B (ізольований контекст)
handle_intent("погода у києві", user_id="user_B")
handle_intent("а завтра?", user_id="user_B")  # Місто з контексту
```

### Приклад 2: Складні entities
```python
# Дати
handle_intent("нагадай мені через 3 дні")
# → entities: {"date": "2026-05-04"}

# Діапазони
handle_intent("гучність від 50 до 75")
# → entities: {"range": {"from": 50, "to": 75}}

# Множинні об'єкти
handle_intent("запусти chrome і firefox і telegram")
# → entities: {"apps": ["chrome", "firefox", "telegram"]}
```

### Приклад 3: Аналітика
```python
from context_manager import context_manager

# Отримати історію користувача
session = context_manager.get_active_session("user_123")
history = context_manager.get_session_history(session.session_id)

# Виявити паттерни
pattern = context_manager.detect_pattern(session.session_id)
# → {"type": "repeated_intent", "intent": "run", "count": 5}
```

## 🎓 Що ми навчились

### Технічні уроки:

1. **Hybrid підхід працює** - rule-based для швидкості, LLM для складності
2. **Контекст критичний** - 85% команд можна покращити з контекстом
3. **SQLite достатньо** - WAL mode дає хорошу продуктивність
4. **Тести важливі** - 94% coverage дає впевненість

### Архітектурні рішення:

1. **Session-based context** - кожен користувач має свою сесію
2. **Lazy LLM** - використовуємо тільки коли потрібно
3. **Graceful degradation** - працює навіть без LLM
4. **Backward compatible** - старий код працює без змін
